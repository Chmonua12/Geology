# MCP-механика «Персональная экспедиция»

## Зачем она нужна

После первого маршрута у ученика остаются ошибки по четырём темам: карст, оползни, обвалы и инженерная защита. Новый модуль использует эти результаты, чтобы сделать дополнительную экспедицию по слабой теме. Это не отдельная форма «для галочки»: она продолжает основной учебный сценарий.

## Как устроен сценарий

1. Django-сайт сохраняет прогресс в браузере и отправляет его в Bun API.
2. Ученик открывает конструктор по кнопке на итоговом экране.
3. MCP-инструмент `get_learning_progress` получает прогресс по ID ученика.
4. Ассистент выбирает слабую тему и вызывает `fill_expedition_form`.
5. Bun API сохраняет черновик в SQLite и отправляет его в открытую Vite-страницу по WebSocket.
6. Ученик видит заполненные поля и проверяет их.
7. После явного подтверждения маршрут создаётся формой сайта или MCP-инструментом `create_personal_expedition`.

## Почему создание отделено от заполнения

Заполнение формы обратимо, а создание маршрута является отдельным действием. Поэтому MCP сначала показывает предлагаемые настройки пользователю и не создаёт экспедицию без подтверждения. В схеме инструмента поле `confirmed` принимает только значение `true`.

## Данные

Локальная SQLite-база находится в `mcp-server/data/geology.sqlite` и не попадает в Git. В ней три таблицы:

- `progress` — последний прогресс ученика;
- `drafts` — последний черновик формы;
- `routes` — созданные маршруты.

Персональные данные не запрашиваются. ID создаётся случайно и хранится в `localStorage` браузера.

## Демонстрация на защите

1. Запустить Django: `python manage.py runserver`.
2. Запустить Bun и Vite: `bun run dev`.
3. Пройти часть основной экспедиции и специально допустить ошибку.
4. Открыть персональную экспедицию на итоговом экране и скопировать ID ученика.
5. Попросить MCP получить прогресс и заполнить форму по слабой теме.
6. Показать, что поля меняются без перезагрузки страницы.
7. Проверить параметры и создать маршрут.

## Проверка без MCP-клиента

Работу канала можно проверить обычным HTTP-запросом. При открытой Vite-странице запрос к `/api/internal/draft` обновит форму по WebSocket:

```powershell
$body = @{
  learnerId = "student-demo"
  topic = "landslide"
  difficulty = "medium"
  taskCount = 4
  hintMode = "on-demand"
  reason = "Повторить признаки оползня после ошибок."
} | ConvertTo-Json

Invoke-RestMethod -Method Post -Uri http://127.0.0.1:3001/api/internal/draft -ContentType application/json -Body $body
```
